# 微信业务接口面板

[返回 README](../README.md) · [业务调用约定](wechat-business.md) · [开发与维护](development.md)

面板运行在 Python WS 插件中，通过本地浏览器查看微信消息、填写业务参数并检查 JSON 结果。内置目录包含 85 个业务方法，实际能力以宿主为准。

## 安装与启动

先按 [README 的 Python 安装步骤](../README.md#运行-python-示例)安装 `lwplugin` SDK 和依赖。以下命令均在仓库根目录执行。

### 模拟模式

```powershell
python ws/python/wechat_panel.py --demo --port 8765
```

打开 <http://127.0.0.1:8765>。模拟模式使用隔离的内存 WS 宿主，不读取实际 endpoint 文件；浏览器连接后会收到模拟文本、表情和图片事件。模拟模式仍需要 SDK，但不需要运行实际宿主或登录微信。

### 连接实际宿主

1. 在宿主中开启 WS 服务，允许 `wechat.business.panel` 接入。
2. 找到该宿主生成的 `config/plugin-endpoint.json`。
3. 使用实际文件路径启动面板：

   ```powershell
   python ws/python/wechat_panel.py --endpoint-file 'C:\path\to\host-data\config\plugin-endpoint.json' --port 8765
   ```

允许接入不会自动启动 Python。升级 SDK 或宿主后，重启相关进程并刷新浏览器。连接多个宿主时，为各面板进程指定不同的 HTTP 端口，例如 `8765` 和 `8766`。

## 页面与操作

| 页面 | 用途 |
| --- | --- |
| 微信消息 | 默认页面，实时显示收到的消息 |
| 接口调试 | 搜索接口、填写字段、编辑 JSON、生成调用代码 |
| 调用结果 | 查看业务状态、JSON 结果和原调用回执 |

一次接口调用的操作顺序：

1. 在右上角明确选择在线微信账号。
2. 进入“接口调试”，按分类或关键词选择接口；页面不会默认选中接口。
3. 查看字段说明并填写参数。必填字段默认加入 JSON，可选字段勾选“传递此参数”后加入，最终以 JSON 编辑器内容为准。
4. 使用“校验 / 代码”检查参数并生成带幂等键的 Python 片段。
5. 选择“提交并等待”或“异步提交”，执行后自动切换到结果页。
6. 需要继续核对时，使用“查询回执”读取原调用结果。

业务参数使用服务原字段名，例如 `toWxid`、`chatRoomId` 和 `voiceTime`。嵌套参数也遵循接口 schema；登录与授权凭据由宿主管理。

## 结果与幂等键

“查询回执”按 `call_id` 或本次幂等键查原调用，不会再次执行。“执行调用”每次点击都会生成新幂等键，代表新的业务动作。

- HTTP 请求成功不等于业务成功，请检查 `status` 和 `error`。
- 等待超时或网络断开后先查询回执，`unknown` 需要核对实际执行结果。
- 刷新页面前保存 `call_id` 或幂等键；页面状态不会替代宿主持久化记录。
- 结构视图会截短长媒体字符串和大集合；复制与下载保留完整 JSON 及大整数精度。

完整状态与默认保留期见[业务调用指南](wechat-business.md#理解调用结果)。跨刷新检索历史、查看积压和人工核对可使用宿主“插件 → 调用记录”。

## 实时消息行为

面板订阅 `wechat.message.received`，通过本地 WebSocket 将事件直接转发给已打开的浏览器。

| 行为 | 说明 |
| --- | --- |
| 显示内容 | 优先 `message.raw.content`，其次 `message.text`，再回退到原始消息 JSON |
| 消息历史 | 不读取宿主数据库，不在面板服务端缓存；刷新或关闭页面后不补查历史 |
| 账号选择 | 右上角选择仅影响接口调用，不筛选实时消息 |
| 消息过滤 | 宿主的 Lua / WS prefilter 先运行，被拦截的消息不会到达面板 |

例如，`message_filter` 开启“过滤非文本消息”时，表情消息也会被拦截。关闭该选项后只影响之后收到的消息，面板不会补放已过滤事件。

## 连接范围

面板 HTTP 服务仅监听 `127.0.0.1`。浏览器通过本地面板调用 SDK，宿主连接令牌不传给浏览器。账号登录、业务授权和授权恢复由宿主管理。

## 目录更新与测试

日常运行使用仓库内置的 `catalog.json`，无需访问私有仓库或重新生成。维护者更新目录和运行测试的步骤见[开发与维护](development.md)。

# 微信群管家（Go）

本地 WS 插件，内嵌中文数据面板，支持自动群列表、成员动态、邀请人排行和日常群管理。入群、离群默认只记录日志，群消息提示分别配置。SQLite 与日志保存在自己的目录，不改写宿主消息库。

[Go SDK](../README.md) · [程序入口](main.go) · [完整名单验证](internal/manager/snapshot.go) · [事务与差集](internal/manager/store.go) · [调度与通知](internal/manager/manager.go)

## 构建与运行

0.3.2 的前端采用 React / TypeScript / Tailwind CSS，构建需要 Node.js 22.12+ 和 Go 1.26+。运行机器不需要 Node.js、Go、Python 或 SQLite 动态库：前端资源随单个可执行文件内嵌，离线可用。从完整源码仓库进入此目录，相邻 SDK 通过本地 replace 引用。

修改前端后，先在 `frontend/` 安装锁定依赖并生成 Go 内嵌资源：

```powershell
cd frontend
npm ci
npm run typecheck
npm run lint
npm test
npm run build
cd ..
```

再编译插件。仅修改 Go 源码、且已有当前版本的内嵌资源时，可以直接执行此步骤：

```powershell
go test ./...
$env:CGO_ENABLED = '0'
go build -trimpath -ldflags='-s -w' -o dist/group-manager.exe .
./dist/group-manager.exe
```

Linux：

```sh
CGO_ENABLED=0 go build -trimpath -ldflags='-s -w' -o dist/group-manager .
./dist/group-manager -endpoint-file /path/to/plugin-endpoint.json
```

先在 Desktop 的“插件 → WS 插件”启动服务，并允许插件 `wechat.group-manager` 接入。将宿主生成的 `config/plugin-endpoint.json` 复制到 `group-manager.exe` 旁边，直接运行即可，无需每次指定路径。文件放在当前工作目录或其 `config/` 下同样可以发现。显式 `-endpoint-file` 与环境变量仍优先；复制的文件在宿主重置 token 后需要更新。

打开 [本地面板](http://127.0.0.1:8766)，选择微信账号，等待自动加载普通微信群及群名称、备注。点击“开启记录”，首次只保存现有成员，后续变化才生成入群/离群日志。自动目录不保证包含微信未返回的群，可手动添加已知群 ID。

## 面板与群管理

| 页面 | 功能 |
| --- | --- |
| 数据概览 | 已记录群数、成员总数、期间新增/离群、按本地日期汇总的趋势、邀请贡献榜和最近动态 |
| 群聊管理 | 自动同步普通群、群名与备注，搜索群，开启/暂停记录，管理群资料与成员 |
| 邀请人统计 | 按账号和群筛选，今天/7/14/30 天新增贡献，当前成员来源，来源未知人数 |
| 成员动态 | 搜索昵称/ID、按群和类型筛选，离线补记标识、通知结果核对，最近 200 条导出 CSV |
| 操作记录 | 持久保存最近操作，显示排队、成功、失败或待确认结果，查询原操作 |
| 偏好设置 | 深色/浅色/跟随系统、日志保留、同步间隔、连接方式说明；消息提醒在各群内单独配置 |

群管理窗口提供服务端现有接口：查看/设置公告、设置群名称、仅自己可见的群备注、设置或清除本人群昵称、显示成员群昵称、保存/移出通讯录、查看群二维码、成员列表及邀请来源、移出成员、添加/移除管理员、转让群主、退出群。另可使用原始二维码链接加入普通群或企业互通群，或确认本人收到的邀请链接。创建群、面对面建群、直接拉人和发送入群邀请均未开放。

普通群提供上述完整入口。企业互通群仅开放服务端实际支持的资料、名称、公告、本人昵称、昵称显示、通讯录和退出等操作，不将基础资料冒充完整成员明细。微信按实际群主/管理员权限校验操作；程序不会自动升级为其他写操作。

**入群审批暂不实现。** `ConsentToJoin` 是当前账号确认本人邀请，不能替代群主审批他人申请；此入口的名称和确认内容均按“本人邀请”展示。

## 邀请来源与统计口径

完整成员详情中的 `inviterUserName` 作为邀请人 ID，与成员昵称分开保存。扫码加入的成员若有该字段，同样纳入统计；字段为空时显示“来源未知”，不凭系统提示文字推断邀请人，也不把每次扫码一律计为某人的邀请。暂不区分扫码/链接等具体加入方式。

“当前成员”统计最新已保存名单中带邀请来源的成员，包含首次读取的已有成员；“期间新增”仅统计开始记录后，由两次完整名单对比发现的入群成员。首次读取不计新增。相同邀请人在不同账号和群中分别统计；历史新增保留发现时的邀请人，后续改昵称或再次检查不会重复计数。期间数据受日志保留天数限制。

## 本地界面组件

0.3.2 使用统一的 React 组件、CSS Variables 主题和提亮的中性灰配色，以蓝青色点缀图表与导航图标。深色为默认主题，可切换浅色或跟随系统；选择保存在当前浏览器。侧边栏支持收缩与移动端抽屉，页面共用布局、表格、筛选、确认弹窗及加载/空/错误状态。图标使用 lucide-react，成员趋势使用 ECharts，并以真实接口聚合结果绘制。

组件采用 shadcn/ui 的组织与 API 约定，底层交互使用 Radix，源码位于 `frontend/src/components/`。账号选择支持搜索和在线状态，所有浮层随主题切换。键盘、焦点、禁用状态和异步确认由共用组件处理；表格分页明确针对已加载记录，不冒充服务端总量。

前端只在构建阶段需要 Node.js；正式运行不访问 CDN。`npm run build` 将 Vite 产物从 `frontend/dist/` 同步到 `internal/manager/web/`，随后由 Go embed 内嵌。旧的原生 JS/CSS 迁移备份已清理，当前只维护 React 前端。源码目录、设计 Token、组件示例和开发命令见 [前端维护说明](frontend/README.md)。

Go 仅对入口 HTML 注入每次请求独立的样式 nonce，供组件浮层的滚动锁定样式使用；同源脚本、Host/Origin 和 JSON 请求检查仍保留，业务 API 及数据结构不变。

| 参数 | 默认值 | 含义 |
| --- | --- | --- |
| `-endpoint-file` | 自动发现 | 也可使用 LW_PLUGIN_ENDPOINT_FILE |
| `-listen` | `127.0.0.1:8766` | 本地设置页，仅允许回环 IP |
| `-data` | `data/group-manager` | 相对工作目录的数据目录 |

服务化运行请显式指定绝对 -data，避免工作目录变化后使用新基线。服务器的设置页可用端口转发访问；远程连接宿主可用 SDK 的 LW_PLUGIN_URL / LW_PLUGIN_TOKEN。插件需常驻，宿主允许接入不等于自动启动进程。

## 判定规则

首次有效完整名单只建立基线，不将所有现有成员报为入群。群资料或系统消息线索触发合并核对；校验调用状态、baseResponse.ret、目标群、serverVersion、infoMask、人数、唯一成员 ID 和当前账号是否仍在名单内，合格后才计算差集。

新增记 joined，消失记 left，来源 member_snapshot_diff，没有额外证据时 reason=unknown，不推断主动退出还是被踢。快照与审计在一个 SQLite 事务中提交；失败、部分名单、旧版本、同版本冲突均不推进基线。昵称变化不产生进退群事件。

chatroomVersion/chatroomInfoVersion 与详情 serverVersion 不混用。eraseChatRoomMemberData 是刷新线索，不清空名单；delchatroommember 系统消息不直接判定退群，服务端实测中它也可能是带撤销操作的入群提示。完整成员监控只支持普通群 @chatroom，企业互通群基础名单不用于退群差集。

## 设置及默认值

| 项目 | 默认行为 |
| --- | --- |
| 成员新增/离开审计 | 开启监控后始终记录 |
| 入群、离群群消息 | 分别关闭，可逐群打开 |
| 事件合并 | 1000 毫秒 |
| 同群查询间隔 | 30 秒，同群最多一条在途查询 |
| 全局并发 | 两条成员查询 |
| 账号弱提示核对 | 60 秒，每轮最多轮转五个关注群 |
| 关注群定时核对 | 关闭；开启后至少 60 秒 |
| 审计保留 | 30 天，不确定的通知不自动清理 |

selector 没有群 ID。只有 server_push 且含 bit 4 才触发有限弱核对，不等于退群。查询期间的新提示会留下后续核对；只读失败最多三次有限恢复，然后等待新提示或手动操作。

消息模板支持 {name}、{wxid}、{group}、{count}。关闭消息开关不影响日志，只影响尚未开始的通知；已提交操作看原回执。首次基线、启动和重连期间的净变化不补发过时提示。

## 日志和断线恢复

每次插件重连或账号上线核对关注群。只记录离线期间的净变化并标记 gap；同一成员在两份名单间退出又加入可能没有净差异，无法保证恢复每一次动作。observed_at 是发现时间，不是微信侧精确动作时间。

```text
data/group-manager/
  config.json                 # 业务设置，不保存宿主 token
  group-manager.db             # 成员名单、邀请来源、审计、群目录和操作记录
  logs/group-manager-日期.log  # UTF-8 JSON 行日志
```

SQLite 审计是事实来源，文本日志为可读副本。页面按账号、群、成员关键词和变更类型查询，最多展示 200 条匹配记录。数据库保留期修改用于下一次清理；文本日志按服务器本地日期轮换，新的保留期在重启后使用。

每条通知有稳定幂等键，先落库再提交宿主。超时/断线/崩溃的不确定结果不自动重发，在日志页“核对原回执”。重启时，未开始的旧通知不补发，已在途通知转 unknown。手动重建基线保留历史审计，下一份名单只建基线。

群管理动作同样先落库再执行。页面生成稳定操作编号，重复提交同编号不会新建动作；同编号换内容会拒绝。写操作不自动重试，超时保留原宿主幂等键供查询。正在执行的操作若遇重启标为待确认；尚未开始的排队动作在恢复连接后继续执行。已完成结果不会被晚到的超时覆盖。退出成功后暂停该群记录。

数据库使用 `PRAGMA user_version` 做事务迁移；v1 名单与日志原地保留并升级到 v2，不删除客户数据。新版数据库不允许旧版本程序改写。

## 测试与源码维护

前端检查在 `frontend/` 运行：

```sh
npm run typecheck
npm run lint
npm test
npm run build
```

Go 检查在此目录运行：

```powershell
go test -race ./...
go vet ./...
```

自包含测试覆盖完整性、差集、昵称、事务回滚、重启恢复、重复提示、查询中更新、限频、消息开关、unknown 不重发、配置持久化、同源检查。内部维护者可在相邻 lw-sdk 运行 `node scripts/run_go_plugin_flow.mjs` 验证真实 Rust WS → Go SDK → 群管家 → SQLite 的三阶段合成名单流程；普通测试不需要私有仓库，TestRealRustHost 默认跳过。

浏览器验收使用实际本机接口或明确的空数据实例。`frontend/tests/` 的隔离输入只用于单元测试，不进入正式前端数据；旧人工合成名单预览工具已移除。

服务端使用标准库 net/http 和内嵌静态资源，前端使用 Vite 构建。关键判断有中文注释，协议、调度、存储、组件和页面分别拆分。数据库升级应增加迁移，不删除用户数据库。源码使用 [MIT License](LICENSE)。
